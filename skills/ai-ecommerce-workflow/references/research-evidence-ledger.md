# 公开研究 Markdown 证据账本

本文件规定搜索到分析之间的中间层。目标是让 Agent 先固定来源、观察值和缺口，再写结论；不是保存整站镜像，也不是引入爬虫。

## 何时建立

只要输出包含竞品、价格、排名位置、评论痛点、平台规则或外部事实，就先建立 Markdown 证据账本。简单的一页结论也必须有账本，只是可以更短。

- 宿主支持文件交付，且用户指定了输出目录或任务已有项目目录：保存为 `research-evidence.md`。
- 没有可写目录或用户只要聊天结果：在工作上下文中维护同样结构，并把精简版作为 `公开研究证据表` 交付。
- 不为了保存证据而要求用户先填写长表或先选平台。

## 获取顺序

1. 用宿主搜索、AnySearch、Tavily、Brave Search、agent-reach 或用户选择的公开搜索入口发现候选。
2. 先记录搜索摘要；只对最终可能引用的公开 URL 做单页正文读取。
3. 搜索工具已经返回 Markdown 时直接规范化，不再转一次。
4. 对用户提供的公开 HTML / URL，可选调用 `huashu-md-html` 的 html-to-md、`autocli read` 或宿主等价能力；一次处理选中的页面，不做目录级、翻页或登录态采集。
5. 转换工具不可用或页面拒绝访问时，保留搜索摘要，状态写 `仅发现` 或 `读取失败`，不得补写正文。

## 最小字段

| 字段 | 写法 |
|---|---|
| `source_id` | 稳定短编号，例如 `S01` |
| `status` | `仅发现` / `已读取公开正文` / `用户提供` / `读取失败` |
| `source_type` | 官方文档 / 商品页 / 搜索摘要 / 公开讨论 / 用户文件 |
| `title` 与 `url` | 原标题和可打开链接；用户文件写文件名 |
| `query` | 实际搜索词；用户直接给 URL 时写 `用户提供` |
| `observed_at` | 带时区的观察时间 |
| `market` | 平台、地区、语言和币种；未知就写未知 |
| `evidence` | 可引用原文、页面观察值或结构化字段，不做营销改写 |
| `caveat` | SKU、运费、优惠、登录、时效、页面阻断或不可比原因 |
| `used_for` | 价格带 / 相似性 / 痛点 / 类目规则 / 文案字段等 |

## 分析门

只有状态为 `已读取公开正文`、`用户提供`，或搜索摘要本身明确显示的信息，才能作为外部事实。分析前检查：

- 同一结论是否至少能指向一个 `source_id`；
- `仅发现` 是否被误写成已读全文；
- 页面观察价是否被误写成成交价；
- 搜索顺序是否被误写成稳定自然排名；
- 竞品属性是否被误写成用户商品属性；
- 官方类目规则、研究数据集和第三方教程是否标清优先级。

最终结论使用 `[来源: S01]` 等引用；账本保留 URL、查询词、时间和口径。不要保存登录态页面、个人信息、密钥、整站 HTML 或与结论无关的大段正文。
