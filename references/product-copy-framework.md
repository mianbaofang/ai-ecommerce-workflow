# 商品文案框架

更新日期：2026-07-29（Asia/Shanghai）。本文件用于约束 Agent 生成商品标题、卖点、详情和 FAQ。它不是让模型照抄同一套套话，而是规定**必须使用哪些事实、按什么买家问题组织、哪些字段不得猜测**。

## 一、先建立事实账本

先把输入、公开页面和图片观察整理成下表，再写文案。每个字段只能标记为：

- `已确认`：用户资料、商品包装 / 说明书、品牌官网或可引用公开页面明确给出；
- `图片可见`：只能描述外观，不升级为材质、性能或认证；
- `市场观察`：竞品常见表达，只用于发现买家问题，不得写成自有商品事实；
- `待确认`：没有证据，不进入对外文案。

| 事实组 | 需要记录的内容 |
|---|---|
| 商品身份 | 品牌、品名、型号 / 货号、类目、商品状态、销售地区 |
| 变体与规格 | 颜色、尺寸、容量、数量、版本、适用对象、SKU 差异 |
| 材料与结构 | 成分、材质、表面处理、关键结构；记录证据原文而非近义改写 |
| 功能与条件 | 功能、测量值、使用条件、限制条件、测试方法和来源 |
| 兼容与适用 | 兼容型号 / 尺寸 / 系统、适用场景、不适用边界 |
| 交付内容 | 包装内含物、配件、是否含电池 / 线材 / 工具、赠品条件 |
| 使用与维护 | 安装、使用、清洁、储存、保质期、注意事项 |
| 交易信息 | 价格口径、库存、发货、退换、保修；没有商家政策时不代写承诺 |
| 合规证据 | 认证、检测、产地、许可、专利、环保或健康声明及可引用来源 |

同一事实在标题、属性、SKU、主图文字、详情和 FAQ 中必须一致。市场搜索只能帮助发现关键词、同类卖点和买家疑虑，不能替自有商品补齐材料、性能、认证或服务承诺。

## 二、统一写作骨架

### 1. 标题

默认顺序：

```text
[品牌（有则写）] + [准确品名] + [1-2 个可验证差异点] + [关键规格 / 变体] + [适用对象或场景]
```

- 先出现买家用于识别商品的品名和关键属性；移动端可能截断，重要信息靠前。
- 只保留影响选择的词，不重复品名、不堆同义词、不借用无关品牌。
- 促销、排名、稀缺、绝对化和未经证实的效果词不进入标题。
- 平台字符上限按当前商家后台复核；参考文件不把易变化的长度当永久规则。

### 2. 一句话定位

用一句自然语言回答：`这是什么 + 适合谁 / 什么情境 + 最重要的已确认差异`。没有证据时，不用“高端、专业、严选、升级、黑科技、必备”等空词补位置。

### 3. 核心卖点

每条按以下顺序写，不必机械显示标签：

```text
可验证事实 -> 对买家的实际意义 -> 适用条件或边界
```

示例：`单 USB-C 口最高 30W 输出，可给支持相应协议的手机、平板或轻薄本供电；实际功率取决于设备、线材和充电协议。`

每条只讲一个购买理由。若“实际意义”需要额外推断，就只写事实和待确认项。

### 4. 详情正文

按买家决策顺序组织，而不是按模型想到什么写什么：

1. 适合谁、解决什么具体情境；
2. 关键规格和选择理由；
3. 尺寸、兼容、使用方法或效果条件；
4. 包装内含物、变体差异；
5. 限制、维护、注意事项和不适用情形；
6. 商家已经确认的物流、售后或质保信息。

短页面可以合并段落，但不得删掉影响购买判断的限制条件。

### 5. 规格、包装与 FAQ

- 规格表只列已确认值，单位统一；未知值显示在内部待确认清单，不以占位话术发布。
- 包装清单逐项写数量，避免买家把展示道具当成随附物。
- FAQ 优先回答从竞品评论、搜索联想和类目经验中发现的购买阻力，但答案仍只使用自有商品事实。
- 默认 FAQ 顺序：尺寸 / 兼容 -> 核心性能条件 -> 使用维护 -> 包装内容 -> 售后或限制。

### 6. 关键词

关键词分为 `品类词、属性词、规格词、场景词、问题词`。标题只放最关键、最自然的一组，其余进入属性、正文或平台允许的后台字段。不得把竞品品牌、无关热词或搜索结果标题直接搬入文案。

## 三、品类模块

先映射到最接近的模块，再读取该行字段。若无法确认品类，只应用通用骨架，并最多询问 1-3 个会影响购买或合规的关键问题。

| 品类模块 | 写作前必须核对的专属字段 | 主要风险 |
|---|---|---|
| 服装与鞋靴 | 品类、适用人群、尺码表、版型、面料成分、颜色 / 图案、闭合方式、季节、洗护、模特与试穿数据 | 凭图片猜面料；把体感写成保暖 / 塑形保证；尺码与 SKU 不一致 |
| 美妆与个护 | 产品形态、净含量、适用肤质 / 发质、全成分、使用方法和频率、生产 / 有效信息、注意事项、许可或检测 | 医疗化功效、绝对安全、过敏保证、虚构成分和使用结果 |
| 食品、饮料与营养品 | 净含量、配料、过敏原、营养信息、产地、生产 / 保质信息、储存、食用或冲调方法、适用限制 | 疾病预防 / 治疗、减重保证、遗漏过敏原、日期与批次混写 |
| 消费电子与数码配件 | 型号、端口、输入 / 输出、电压电流和功率、协议、兼容清单、电池、尺寸重量、包装、保修、认证 | “全兼容 / 最快 / 绝不发热”；忽略线材、设备和协议条件 |
| 家居、厨房与小家电 | 材质、尺寸、容量、功率、温度范围、适配炉具 / 电压、清洁、安装、包装、食品接触证据 | 凭外观写食品级；耐热、防漏、承重或可机洗无测试 |
| 家具与家饰 | 展开尺寸、材料、表面处理、承重测试、安装方式、适用空间、包装尺寸、养护 | 不写门宽 / 安装条件；把估算承重写成保证 |
| 运动与户外 | 尺寸重量、材料、适用项目 / 水平、天气 / 防水等级及标准、使用条件、安全说明、配件 | 把生活防泼水写成防水；安全保证；越过项目或天气边界 |
| 母婴与玩具 | 年龄分级、尺寸、材料、小零件 / 电池、监护要求、认证、清洁、包装 | 虚构益智 / 发育功效；遗漏窒息、电池或监护提醒 |
| 珠宝、钟表与配饰 | 主材 / 镀层、宝石天然或合成属性、尺寸重量、链长 / 圈口、扣型、机芯、养护 | 把镀层写成实金；未经证实的保值、低敏和宝石等级 |
| 宠物用品与宠物食品 | 适用物种、体型 / 生命阶段、尺寸、材料或配料、喂食 / 使用量、储存、安全、兽医依据 | 医疗功效、对所有宠物通用、剂量和体型不匹配 |
| 汽配、工具与工业品 | 零件号、适配车型 / 年款 / 接口、尺寸、材料、性能参数、安装、标准、包装、保修 | 宽泛兼容、忽略专业安装和安全标准、错误扭矩 / 电气参数 |

分类字段可以参考 Shopify Standard Product Taxonomy、MEP-3M 等公开分类做**候选类目和提问提示**，但不得因为分类表存在某个属性就替商品生成属性值。

### 中国平台类目路由

面向淘宝 / 天猫、京东、拼多多、抖音或快手时，按以下顺序处理：

1. 先用本文件的品类模块识别大类和高风险字段。
2. 再确认目标平台的当前叶子类目 / 具体商品类目；用户已在后台选择类目时优先采用该选择。
3. 能从官方公开文档或用户授权数据取得类目必填属性时，官方属性覆盖通用分类提示和 GitHub 数据集。
4. 官方字段只决定“要问什么、放在哪里”，不能替商品生成值；缺失值保持 `待确认`。
5. 官方页面动态加载、需要授权或无法读取时，询问用户已选后台类目，或明确标记 `上架前按当前类目规则确认`，不杜撰接口、字段或枚举值。

研究型 GitHub 分类、第三方教程和搜索摘要都不能覆盖平台官方类目属性。详细来源和验证状态见 `copy-research-basis.md`。

## 四、平台适配层

平台适配只改变结构、长度和语气，不改变事实账本。

| 平台 | 输出结构和写法 |
|---|---|
| 淘宝 / 天猫 | 标题突出品名、基本属性和规格；卖点兼顾搜索词与购买决策；详情把 SKU、规格、赠品、适用和限制写清。标题、主图、属性、详情保持一致，不放无关品牌。 |
| 京东 | 先写准确品名、品牌 / 型号和硬规格，参数表优先；对家电、3C 等品类突出可核对型号、接口、能效 / 认证和售后条件。 |
| 拼多多 | 标题保持具体、可搜索，价格或优惠只引用当前真实活动；正文先说明规格数量和适用场景，不用“全网最低”等无法证明的比较。 |
| 抖音电商 | 标题短而可识别，至少含明确品名和关键属性；口播 / 商品卡文案先给一个具体使用情境，再给事实和条件。避免符号堆砌、重复品名和未实测演示结论。 |
| 快手电商 | 用直白口语说明是什么、规格多少、适合谁；直播卖点和商品页必须一致，限时、库存和赠品只写可兑现信息。 |
| Amazon | 输出标题、五条要点、描述、关键词和 FAQ。标题先写品牌 / 品名与关键属性；要点讲利益但必须落在事实；兼容、性能、认证和比较声明带条件。具体字符限制按站点和类目后台复核。 |
| eBay | 标题优先使用准确品名、品牌 / 型号、尺寸、颜色和状态；完整填写 Item specifics；描述说明物品状态、缺陷、包装内容、尺寸和发货 / 退换口径。 |
| Etsy | 标题清楚说明物品是什么，避免把标签堆成难读标题；描述强调材料、尺寸、制作 / 个性化选项、处理时间、养护和品牌故事；标签不得补造材料或工艺。 |
| Shopify | 产品名保持自然；正文可使用更明显的品牌语气和场景故事，但仍要提供规格、变体、交付、维护、FAQ、SEO 标题和 Meta 描述。每个产品页写独立文案。 |
| AliExpress | 标题使用买家可搜索的品名、关键规格、兼容和数量；正文适合跨语言扫描，优先参数表、尺寸、包装、使用步骤和兼容边界，避免文化性双关和不可翻译口号。 |

## 五、生成前后硬校验

生成前：

1. 确认品类模块和目标平台；
2. 列出 `已确认`、`图片可见`、`市场观察`、`待确认`；
3. 检查品类模块的关键字段，缺少会造成误购或合规风险的字段时再询问用户；
4. 中国平台先检查当前叶子类目和官方必填属性；无法公开确认时，明确要求用户提供已选后台类目或在上架前按当前规则复核。

生成后逐句检查：

- 每个数字、材料、功效、认证、兼容、售后和比较词能否指向证据；
- 标题、SKU、规格表、卖点、图片文字和 FAQ 是否一致；
- 每个卖点是否同时回答“事实是什么、对谁有用、什么条件下成立”；
- 是否出现空泛套话、关键词堆砌、AI 常用总结句或所有平台同一段文案；
- 是否明确写出尺寸、兼容、包装、维护或安全中会影响退货的条件；
- 是否把竞争对手的评价、销量、认证或功能错写成自有商品事实。

不通过校验的句子删除或改为内部 `待确认`，不得用更模糊的营销词掩盖缺失。
