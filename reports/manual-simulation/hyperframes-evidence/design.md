# Design Truth

## 目标

这不是“AI 一键生成商品页”的广告，而是一段能让首次安装用户立即理解 Skill 边界的 20 秒证明：给描述、公开链接或图片中的任意一种即可开始；系统先保存可追溯的公开证据，再按平台叶子类目组织事实和文案，经过自然化与违规表达审核后，才进入不同平台的图片和文案交付。画面要让人感到流程可靠、克制、可检查，而不是神奇、自动、无条件成功。

## 受众与观看场景

主要受众是第一次打开 GitHub README 的电商运营、独立卖家和会安装 Agent Skill 的用户。他们通常只会看一遍 GIF，没有声音，也不会暂停阅读长文。因此每幕只能保留一个主要判断，中文标题应在一秒内读懂，细节作为“可信纹理”而不是阅读任务。源画面为 1920x1080、16:9，最终 README GIF 为 960x540、5fps、20 秒，符合 GitHub Launch 的预览媒体规范。

## 视觉母题

母题是“发布工作台”，不是软件 Dashboard。真实商品照片、公开网页剪报、分类样品、红线校样和平台交付物依次进入同一张编辑桌。五幕共享纸张、装订线、批注与审核印记，但不共享同一种面板模板。每幕只有一个主视觉：商品、来源、样品、红线稿、交付墙。辅助信息围绕主视觉排列，不把所有内容塞进等宽卡片。

## 图像角色

- `product-master.png`：用户提供的商品测试图，只在第 1 幕完整出现；第 5 幕最多出现一次小缩略图。
- `source-domestic-10-platforms.png` 与 `source-crossborder-10-platforms.png`：真实公开网页证据，主要服务第 2 幕和第 5 幕。
- `charger-fixture.png`：无品牌、单口 USB-C 充电器的生成测试样品，只服务第 3 幕，画面必须标注其测试性质。
- `proofreading-desk.png`：无可读虚构文字的编辑校对氛围图，只作为第 4 幕底层质感；真正可读的违规词和修订意见仍由 HTML 排版生成。

## 形式与排版

色彩沿用暖白 `#f2efe7`、墨黑 `#1d2528`、墨绿 `#2f725d`、朱红 `#c64836`、审核黄 `#e2b93f`，但每幕只允许一个强调色占主导。展示字使用现有中文黑体，正文保持紧凑，不使用负字距，不用渐变、发光、圆角胶囊或嵌套卡片。可用硬边裁片、纸张阴影、装订孔、裁切线和红笔标记建立实体感。所有正文在 16:9 和缩小到 960x540 后仍应可辨。

## 动效原则

保留单一暂停 GSAP 时间轴。每幕使用 2-4 个可解释动作：纸张滑入、裁片错位落下、分类路径逐级点亮、红线手写揭示、交付物装订归位。禁止连续漂浮、弹簧堆叠和每个元素各自表演。场景切换通过上一幕工件离桌、下一幕工件入桌完成；背景不再全程移动大网格。所有动作必须确定性、可 seek，最终 `npm run check` 零错误后才渲染。

## 文案与边界

只陈述已经由项目测试证明的能力。不得声称实时成交价、销量、搜索排名、平台审核必过或自动发布。公开网页仅作为来源证据，发现链接和读过正文必须分开；生成测试样品不能冒充商家真实商品；图片是否可发布仍需逐张复核。最终画面必须明确区分“核心流程通过”和“图片逐张复核”。
